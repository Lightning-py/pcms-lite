# Языки эталонных решений

Список языков участников фиксирован: C, C++, Python. Настройки ниже относятся
только к эталонам Polygon и не добавляют языки в форму отправки решений.

Для эталона читается `assets/solutions/solution[@tag="main"]/source/@type`.
C/C++ компилируются из исходников, Java 8/11/17/21 — OpenJDK 21, Python 3 —
системным Python. Java-файлы переименовываются по имени public class. Java-чекер
собирается с библиотекой testlib4j из пакета. Весь код, включая библиотеку и
компиляторы, исполняется через isolate.

Есть базовые профили для `python.2`, `python.pypy`, `python.pypy3`, `ruby`, `perl`,
`php`, `javascript`, `go`, `rust`, `pascal`, `haskell`, `ocaml`, `d`, `csharp.mono`.
Их runtime, точные идентификаторы и совместимость нужно проверить для своего
экспорта Polygon. Установщик автоматически ставит только C/C++, Python3, PyPy3,
OpenJDK21; остальные инструменты устанавливает администратор.

Любой другой идентификатор языка можно подключить без правки кода импортёра.
Создайте root-owned `/etc/pcms-lite/reference-languages.json`, доступный на чтение
пользователю `pcms`. Файл сохраняется при переустановке. Пример двух профилей:

```json
{
  "rust.2021": {
    "source": "main.rs",
    "compile": ["/usr/bin/rustc", "--edition=2021", "-O", "main.rs", "-o", "main"],
    "artifact": "main",
    "run": ["/box/main"]
  },
  "javascript.node": {
    "source": "main.js",
    "run": ["/usr/bin/node", "main.js"]
  }
}
```

Ключ должен точно совпадать с `source/@type` из XML. Профиль может переопределить
встроенный идентификатор, например для точной старой версии компилятора.

- `source`: имя исходника внутри песочницы.
- `compile`: необязательный список аргументов команды; shell-интерполяции нет.
- `artifact`: один файл результата компиляции, переносимый в песочницу запуска.
  Для native-программы используйте `main`, для JVM/.NET — jar/assembly и явный runner.
- `run`: список аргументов запуска. Для компилируемого профиля по умолчанию `/box/main`.
- Для языка с несколькими выходными файлами используйте доверенный серверный
  wrapper в `/usr/local/bin`, который собирает единый jar/другой артефакт.
  Сам wrapper тоже выполняется внутри isolate.

Runtime должен быть доступен в системных read-only каталогах isolate (`/usr`,
`/bin`, `/lib`); пользовательские `/opt` и весь `/etc` не открываются.
Для Ubuntu OpenJDK отдельно доступен только `/etc/java-21-openjdk`, read-only.
Сетевого доступа нет. При необходимости настройте wrapper с параметрами runtime,
явными путями конфигурации и временным каталогом `/box`.

Ограничения подготовки: компиляция профиля — 120 CPU-секунд/1 ГиБ, отдельный
запуск эталона — max(10 секунд, 5 × лимит задачи), память max(1 ГиБ, лимит задачи),
64 процесса/потока. Дисковые и выходные лимиты isolate остаются включены.
Профили не считываются из ZIP. Неизвестный язык или отсутствующий runtime приводят
к понятной ошибке импорта, а не запуску программы на хосте.

Полная совместимость со всеми языками и версиями Polygon из коробки не заявляется:
для устаревших и Windows-only компиляторов нужен отдельный совместимый профиль/runtime.
Это расширяемый механизм, а не автоматическая установка произвольных компиляторов
по имени из недоверенного архива.
