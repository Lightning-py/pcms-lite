# PCMS Lite

Первая версия собственной тестирующей системы для Ubuntu: минимальный русский
интерфейс, локальная проверка C17, C++20 и Python 3, импорт пакетов Polygon с готовыми ответами или эталонным решением.
DOMjudge, ejudge и внешние сервисы проверки не используются.

## Что реализовано

- Контесты по времени и бессрочные тренировки; закрытие задач до старта.
- Учётные записи администратора и участников, хеширование паролей, CSRF-защита.
- Загрузка исходника файлом или вставкой кода, очередь SQLite, отдельные workers.
- Вердикты AC, WA, PE, CE, RE, TLE, MLE, OLE и JE; протокол по тестам.
- Автоматическое обновление статуса открытой посылки, перепроверка администратором.
- Таблица ICPC; для контестов с баллами — сумма лучших результатов по задачам.
- Импорт задачи и набора задач/контеста Polygon, включая порядок из contest.xml.
- Отдельная песочница для компилятора, каждого запуска решения и каждого чекера.
  Эталонные ответы не передаются в песочницу решения.

Это MVP для пилотного запуска. Прежде чем проводить соревнование, выполните
интеграционные тесты на целевом Ubuntu-сервере и проверьте реальные пакеты своего
контеста. Автоматические тесты приложения не заменяют проверку настройки isolate.

## Установка на сервер одной командой

На Ubuntu 24.04+ из распакованного проекта:

```bash
sudo bash install.sh --domain judge.example.org --email admin@example.org
```

Подставьте свой домен и email. Скрипт устанавливает зависимости, создаёт базу,
администратора, изолированный проверяющий сервис и службы systemd. Для nginx
добавляется отдельный файл; другие сайты и nginx.conf не переписываются.
Без `--email` сайт работает по HTTP. Полное описание, требования к серверу,
повторный запуск и восстановление — в [INSTALL.md](INSTALL.md).

## Локальный запуск интерфейса

Требуется Python 3.11+. Команды выполняются из корня этого проекта.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock
.venv/bin/pip install --no-deps -e .
.venv/bin/pcms init
.venv/bin/pcms user admin --admin
python3 tools/make_demo.py demo-contest.zip
.venv/bin/pcms import demo-contest.zip --title 'Пробная тренировка'
.venv/bin/pcms serve
```

Откройте http://127.0.0.1:8000. Пароль задаётся интерактивно; встроенных паролей нет.
Участники создаются на странице «Администрирование» или командой `pcms user alice`.
Без worker посылки и веб-импорты сохраняются в очереди. CLI-импорт пакета с готовыми ответами работает без isolate; для подготовки отсутствующих ответов isolate обязателен.

По умолчанию БД, пакеты и ключ сессий находятся в `data/`. Можно задать абсолютный
путь переменной `PCMS_DATA`. Все процессы должны использовать один и тот же путь.
Каталог данных не должен находиться внутри `/usr`, `/bin`, `/lib`, `/lib64`, `/dev`
или `/proc`: эти системные деревья видны из isolate. Для сервера используйте
`/var/lib/pcms-lite`, код приложения храните в `/opt/pcms-lite`.

## Импорт Polygon

Поддерживаются пакеты с готовыми входными тестами. Если ответов `tests/*.a` нет,
worker создаёт их запуском решения с `tag="main"` в isolate и проверяет чекером.
Скрипты `doall.sh`/`.bat` и готовые программы пакета не запускаются.
Чекеры: C++ testlib с `testlib.h` и Java testlib4j с `testlib4j.jar`.
Java-библиотека из пакета загружается только внутри песочницы.
Windows-пакет можно импортировать, если его исходники совместимы с серверными
компиляторами; Wine и запуск `.exe` не используются.

Импорт через админку выполняется в фоне: статус, текущий тест подготовки, ошибка
и ссылка на готовый контест видны в разделе «Импорты». Нужен запущенный worker.
После перезапуска его незавершённый импорт начинается заново. Контест публикуется
только после успешной подготовки всех задач. Загрузки удаляются после завершения.
CLI `pcms import` выполняет подготовку синхронно и использует отдельный box 997.

Языки **участников** остаются C17, C++20 и Python 3. Языки **эталонов** задаются
отдельно: встроены C/C++, Python и Java; дополнительные языки подключаются
администратором через профили компиляции/запуска. Установщик ставит OpenJDK 21
(также для исходников Java 8/11/17) и PyPy3. Это не обещание наличия всех версий
компиляторов Polygon на Ubuntu. Для каждого дополнительного языка нужен
совместимый runtime. См. [REFERENCE_LANGUAGES.md](REFERENCE_LANGUAGES.md).

Баллы: `each-test`, `complete-group`, зависимости групп; проверяются все тесты,
баллы зависимой группы начисляются только при прохождении её зависимостей.
Нулевые баллы/метки групп без положительной суммы сохраняют режим AC/WA.
При наличии задач с баллами таблица использует лучшие посылки по каждой задаче;
за обычную задачу в таком смешанном контесте начисляется 100 баллов за AC.
Протокол показывает все выполненные тесты: политики скрытия `feedback-policy`
не воспроизводятся. Чекеры с частичными баллами через exit code 7 не поддерживаются.

Для контеста упакуйте в один ZIP:

```text
contest.xml          # необязательно; дескриптор Polygon
sum.zip              # полный Linux-пакет первой задачи
product.zip          # полный Linux-пакет второй задачи
```

Либо вместо внутренних ZIP положите распакованные каталоги задач с `problem.xml`.
Поля `url` из contest.xml сопоставляются с URL/short-name вложенных задач. Также
поддерживается локальное поле `path`, указывающее на распакованный каталог задачи.
Контест должен содержать все перечисленные полные пакеты. URL сами не скачиваются.
Без contest.xml пакеты сортируются по пути и получают A, B, C…; при добавлении
в существующий контест автоматически выбираются свободные обозначения.

```bash
.venv/bin/pcms import contest.zip --title 'Контест №1'
.venv/bin/pcms import another-problem.zip --contest 1
```

Веб-интерфейс также позволяет назначить начало в UTC и длительность нового контеста.
Импорт выполняется целиком: если одна задача некорректна, новые задачи не добавляются.
Ограничения: 128 МиБ на веб-загрузку, 2 ГиБ после распаковки, 30000 файлов,
256 МиБ на файл, 100 задач и 2000 тестов на задачу.

Поддерживаются обычные задачи stdin/stdout и ввод/вывод через отдельные именованные
файлы в рабочем каталоге. В первой версии не поддерживаются интерактивность,
несколько testset, задачи с grader, генерация отсутствующих входных тестов,
подключение к Polygon API, виртуальное время участников и заморозка таблицы.
Условия в LaTeX не компилируются — экспортируйте HTML/PDF из Polygon.
Лимиты задачи одинаковы для всех языков, коэффициентов для Python пока нет.
Для файлового ввода/вывода имена `main`, `main.py`, `.pcms-input`, `.pcms-stdout`
и `.pcms-stderr` зарезервированы. Импортёр отклоняет неподдерживаемые варианты,
которые он распознаёт, но не является полной реализацией всей спецификации Polygon.

Публичная ссылка Codeforces не даёт полный пакет скрытых тестов.
Нужны пакеты, доступные организатору. Подробнее:
[Polygon API](https://codeforces.github.io/polygon-misc/API).

## Проверяющий сервер Ubuntu

Рекомендуемая стартовая среда: Ubuntu 24.04 LTS, GCC/G++ 13, системный Python 3.12,
Linux >= 5.19, cgroup v2. Точные установленные версии определяет ваш сервер.

1. Установите `build-essential`, `python3`, `python3-venv` и `quota` средствами Ubuntu.
2. Установите актуальный [isolate](https://github.com/ioi/isolate), следуя разделу
   Installing Isolate / Debian packages его официального README. Для режима cgroup
   запустите поставляемый `isolate.service`. Isolate требует setuid-helper, сам
   worker запускается обычным пользователем, не root.
3. Настройте дисковые квоты для UID песочниц на файловой системе каталога isolate
   (`box_root` из конфигурации isolate, обычно `/var/local/lib/isolate`).
   Используйте отдельный раздел/том ext4 с поддержкой user quotas. Включение квот
   зависит от разметки диска; **не переносите рабочую файловую систему вслепую**.
   Команда `isolate --box-id=999 --cg --quota=262144,4096 --init` должна успешно
   завершаться от пользователя worker; после проверки выполните
   `isolate --box-id=999 --cg --cleanup`.
4. Проверьте установку от пользователя worker:

```bash
.venv/bin/pcms doctor
PCMS_INTEGRATION=1 .venv/bin/python -m unittest discover -s tests -p test_integration.py -v
.venv/bin/pcms worker --box-id 0
```

`doctor` использует box 999, интеграционные тесты — box 998. Эти ID должны быть
свободны. Каждый параллельный worker должен иметь уникальный box ID на всём хосте.
Для начала достаточно одного worker; второй запускается с `--box-id 1`.

Если isolate, cgroups или квоты не работают, worker останавливается **до приёма
заданий**. Режима небезопасного запуска без песочницы нет. Ошибки инфраструктуры
после получения задания дают JE и доступны администратору в протоколе.
После перезапуска worker повторно ставит в очередь свои прерванные задания.

Песочница ограничивает время CPU и реальное время, память cgroup, число процессов,
число открытых файлов, общий объём диска (256 МиБ, 4096 inode) и размер каждого
выходного файла (16 МиБ). `/tmp` и `/dev/shm` не предоставляются; временные файлы
компилятора размещаются в `/box`. Интернет и каталоги приложения не монтируются.
Пакеты с очень большими тестами могут не поместиться в дисковую квоту песочницы;
проверяйте такие задачи до контеста. MLE фиксируется при cgroup OOM; если программа
сама обработала отказ выделения памяти и аварийно завершилась, возможен RE.

## Службы и HTTPS при ручной установке

Шаблоны расположены в `deploy/`. Они предполагают отдельного системного пользователя
`pcms`, приложение с venv в `/opt/pcms-lite` и доступный этому пользователю каталог
`/var/lib/pcms-lite`. Создайте БД и администратора от `pcms`, задав PCMS_DATA.

После проверки путей установите `pcms-web.service` и `pcms-worker@.service` в systemd.
Для worker 0 имя службы — `pcms-worker@0`. Веб-приложение слушает только
127.0.0.1:8000; перед ним нужен HTTPS reverse proxy. Фрагмент nginx дан отдельно,
домен и сертификат задаются на вашем сервере. `PCMS_HTTPS=1` включает Secure cookie;
для локальной проверки по HTTP эту переменную не задавайте.

Не запускайте Flask development server как публичный production-сервер.
У веб-службы включён NoNewPrivileges; у worker его включать нельзя, поскольку
isolate использует setuid. Код приложения и конфигурацию isolate должен контролировать
администратор хоста. При размещении за прокси стандартный ограничитель входа видит
адрес прокси; для большой группы настройте дополнительный rate limiting в nginx.

Резервное копирование: остановите web/workers и скопируйте весь PCMS_DATA, включая
SQLite, пакеты и ключ сессий. Не копируйте один файл SQLite во время записи без
SQLite backup API. Для восстановления сохраните владельца и права каталога.

## Тесты и структура

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python tools/smoke_http.py
```

Обычные тесты проверяют импорт, откат, ZIP/XML-защиту, авторизацию, CSRF, закрытые
посылки/тесты, очередь, таблицу и логику worker с имитацией песочницы. Интеграционные
тесты по умолчанию пропускаются и запускаются только с PCMS_INTEGRATION=1.
Они действительно компилируют и проверяют C/C++/Python, проверяют AC/WA/CE/RE/TLE/
MLE/OLE и недоступность сети/секрета хоста.

```text
judge/polygon.py    импорт и валидация пакетов
judge/sandbox.py    адаптер isolate и компиляция
judge/worker.py     очередь и цикл проверки
judge/db.py         схема и таблица результатов
judge/web.py        HTTP, авторизация, формы
judge/templates/   интерфейс
judge/static/      CSS и обновление статуса
deploy/            примеры systemd и nginx
tools/make_demo.py демонстрационный контест из двух задач
tests/             тесты приложения и интеграционные тесты
```

Демонстрационный контест синтетический, создан в этом проекте. Его чекер использует
настоящую testlib, сохранённую в tests/fixtures/testlib.h с оригинальными
уведомлениями об авторстве и разрешении использования. Источник и SHA-256 указаны
в THIRD_PARTY.md. Этот пример не подтверждает совместимость со всеми реальными
экспортами Polygon.

## Управление контестом и посылками

На странице контеста администратору доступны «Редактировать контест» и
«Добавить задачи». Название, начало (UTC) и длительность можно менять в любое
время; пустое начало включает бессрочную тренировку. Новые настройки сразу
влияют на доступ к задачам, приём решений и учёт посылок в таблице.

При добавлении пакета задачи или целого контеста прежние задачи и посылки
сохраняются. Совпадающие обозначения новых задач заменяются свободными буквами
без учёта регистра. Подготовка добавленных задач выполняется в фоновой очереди.
Повторная загрузка пакета добавляет новые задачи, а не обновляет старые.

На странице посылки администратор может:

- принять решение: AC и полный балл задачи;
- забанить решение: BAN, без баллов, зачёта и штрафа;
- вернуть автоматический результат.

Причина обязательна; история действий видна владельцу посылки и администратору.
Ручной вердикт хранится отдельно от тестов и не сбрасывается завершением worker
или перепроверкой. Бан относится только к выбранной посылке, другие принятые
решения участника продолжают учитываться. Изменения сразу учитываются в API,
списке посылок и таблице при следующем запросе/обновлении страницы.
