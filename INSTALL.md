# Автоматическая установка на Ubuntu

Установщик запускается **на сервере**, из распакованного проекта. Он рассчитан
на Ubuntu 24.04+ с systemd, cgroup v2 и доступом в интернет. Используйте полноценную
VM или физический сервер: обычный непривилегированный Docker-контейнер не подходит.

## Запуск

Направьте A-запись отдельного поддомена на сервер. Порты 80 и 443 должны быть
доступны снаружи; облачные security groups и внешний firewall настраиваются
у провайдера. Установщик не сбрасывает firewall и не меняет SSH.

```bash
unzip pcms-lite.zip
cd pcms-lite
sudo bash install.sh --domain judge.example.org --email admin@example.org
```

Замените домен и email своими. `--email` включает получение сертификата Let's
Encrypt и означает согласие с условиями ACME. Сертификат получается через webroot;
Certbot не редактирует nginx-конфигурации. Если домен имеет AAAA-запись, она должна
соответствовать доступному IPv6-адресу этого сервера.

Для локальной сети, IP-адреса или первого запуска без HTTPS:

```bash
sudo bash install.sh --domain 192.0.2.10
```

Без `--email` создаётся HTTP-сайт. Позднее можно повторить запуск с тем же доменом
и добавить `--email`. Уже включённый HTTPS при повторном запуске сохраняется.

Дополнительные параметры:

```bash
sudo bash install.sh --domain judge.example.org --email admin@example.org \
  --workers 2 --sandbox-gib 8
```

По умолчанию создаётся один worker и отдельный ext4-образ на 4 ГиБ для песочниц.
Нужны эти 4 ГиБ плюс не менее 2 ГиБ свободного места для приложения и зависимостей;
дополнительное место зависит от загруженных задач. `--sandbox-gib` меняет только
размер **нового** образа: существующий образ не форматируется и не увеличивается.
Worker допускает до 1 ГиБ памяти на компиляцию; учитывайте это при выборе их числа.

## Что создаёт установщик

- Системного пользователя `pcms`, базу, ключ сессий и администратора.
- Отдельное virtualenv с закреплёнными Python-зависимостями.
- GCC/G++, системный Python и зависимости сборки isolate.
- Собственный isolate 2.7, собираемый из фиксированного коммита с проверкой SHA-256.
  Уже установленный системный isolate и его конфигурация не заменяются.
- Пользователя `pcms-sandbox` и свободные subordinate UID/GID для песочниц.
- Отдельный файловый образ ext4 с user quotas и systemd mount unit.
  `/etc/fstab` и существующие разделы не изменяются.
- Службы `pcms-isolate`, `pcms-web`, `pcms-worker@0` и нужные дополнительные workers.
- Отдельный сайт nginx и, по запросу, сертификат с автоматическим продлением.

Приложение слушает Unix-сокет, поэтому не занимает чужие TCP-порты вроде 8000.
Права сокета назначаются группе, указанной для существующего worker-пользователя
nginx. Адрес и слушающие порты других nginx-сайтов не меняются.

Перед публикацией выполняются `pcms doctor` и 11 интеграционных тестов с реальным
исполнением решений. Затем проверяется веб-служба и HTTP-запрос через nginx.
При неисправных квотах/изоляции установка не объявляется успешной и сайт новой
версии не публикуется. Опции обхода этих проверок нет.

## Сохранение nginx

Установщик создаёт только `/etc/nginx/conf.d/pcms-lite.conf`. Он:

- Не переписывает `nginx.conf`, другие файлы в `conf.d` и `sites-enabled`.
- Не удаляет default site и не назначает свой сайт `default_server`.
- Останавливается, если домен уже явно объявлен в другой конфигурации.
- Не перезаписывает файл `pcms-lite.conf`, созданный вручную или другой системой.
- Сохраняет резервную копию прежнего собственного файла при обновлении.
- Выполняет `nginx -t` перед reload и восстанавливает собственный файл при ошибке.
- Устанавливает пакеты с сохранением старых conffile и без принудительного
  обновления уже установленного nginx.

Ожидается стандартное для Ubuntu подключение `/etc/nginx/conf.d/*.conf` внутри
блока `http` и явная директива `user` в конфигурации nginx. Если конфигурация
нестандартная и эти условия не выполняются, скрипт остановится с объяснением,
не пытаясь переписать её автоматически.

## Доступ и повторный запуск

После успешной установки откройте указанный домен. Первоначальные реквизиты:

```bash
sudo cat /etc/pcms-lite/admin-credentials
```

Файл доступен только root. Существующий администратор и его пароль не меняются
при повторном запуске. Если пароль позже изменён отдельно, этот файл остаётся
записью первоначального пароля.

Обновление: распакуйте новую версию в отдельную папку и повторите ту же команду.
Данные сохраняются в `/var/lib/pcms-lite`. Код размещается в
`/opt/pcms-lite/releases/<версия>`, ссылка `current` переключается после проверок.
При ошибке переключения восстанавливается предыдущая версия и её службы.
Предыдущие releases автоматически не удаляются.

Свои конфигурации перед переключением копируются в
`/etc/pcms-lite/backups/<дата>`. Это резервные копии конфигураций, **не backup БД**.
Перед обновлением важных контестов отдельно сохраните данные по инструкции README.

Если получение сертификата не удалось, например из-за DNS, рабочий HTTP-сайт
сохраняется. Исправьте DNS/доступность порта и повторите запуск. Установленные
пакеты ОС, данные, образ песочниц и подготовленные releases при ошибке не удаляются.
Существующая ручная установка в `/opt/pcms-lite` автоматически не заменяется.

Диагностика:

```bash
sudo systemctl status pcms-web pcms-worker@0 pcms-isolate var-lib-pcmsboxes.mount
sudo journalctl -u pcms-web -u pcms-worker@0 -u pcms-isolate -n 100
sudo nginx -t
```

Установщик протестирован локально на сценариях генерации конфигураций,
сохранения чужих сайтов, конфликтов и отката. Полная установка на отдельном
Ubuntu-сервере в среде разработки не выполнялась.

## Если установщик остановил web и worker

Сообщения SIGTERM и `Deactivated successfully` могут быть результатом отката,
а не первичной ошибкой. Смотрите строку «Установка остановлена на этапе…» в
выводе самого install.sh. Проверка сайта повторяет запрос после nginx reload,
поскольку применение новых настроек не обязано завершаться одновременно с
возвратом команды reload. Ошибки curl теперь выводят HTTP-код, а при откате
показываются последние сообщения nginx, относящиеся к сокету PCMS.

Тест MLE намеренно превышает лимит памяти своей песочницы. Запись OOM в журнале
во время этого теста совместима с успешным `Ran 11 tests … OK`; сама по себе она
не означает, что серверу в целом не хватает памяти.

При повторной попытке сохраните вывод (пароль администратора туда не выводится):

```bash
git pull --ff-only
sudo bash install.sh --domain ВАШ_IP_ИЛИ_ДОМЕН 2>&1 | tee pcms-install.log
```

Механизм reload: https://nginx.org/en/docs/control.html
